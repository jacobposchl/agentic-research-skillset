# Scaffold Diagram Guidelines

Use diagrams only when they materially improve understanding of the proposed scaffold.

## Format

Use Mermaid.

## Content

Show only the structural relationships needed to verify the design, such as:

- major files or modules
- important classes or functions
- inputs and outputs
- data or control flow
- boundaries between major stages

## Style

- Keep diagrams concise.
- Prefer conceptual labels over implementation details.
- Exclude incidental helpers, variables, and low-level operations.
- Group related components when useful.
- Use arrows only when the relationship or flow is meaningful.
- Reflect the proposed scaffold accurately.
- Do not introduce components solely to make the diagram more complete.

The diagram should make it easier for the user to evaluate the proposed structure before any code is created.
